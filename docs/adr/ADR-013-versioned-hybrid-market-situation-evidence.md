# ADR-013: Versioned hybrid MarketSituation evidence

- **Status:** Accepted
- **Decision:** Separate the complete `market-situation-v1` analytical candidate universe from its compact immutable selected-result assessment, persist the two contracts through normalized immutable SQL evidence, keep the complete universe out of normal runtime/read-model/UI paths, and expose persistence/host/launcher failure separately from analytical completeness. Correction Batches 1-4 establish domain, persistence, compact current-state/API/Blazor, bounded forensic, terminal-outcome, process-exit, diagnostics, and launcher-validation boundaries; sustained live validation remains later.

## Context

Bounded live validation of complete historical sessions exposed a scalability failure in the current MarketSituation persistence shape. The evaluator considers every eligible level, but `MarketSituationAssessment.EligibleLevels` embeds that complete universe, contributes it to assessment identity, and is serialized into immutable SQL `AssessmentJson`. A representative MSFT assessment was approximately 299.7 MB and SQL persistence timed out.

The analytical result was valid before persistence failed. A persistence failure must not relabel complete `PriorSessionEnhanced` analysis as `CurrentSessionOnly`, replace the selected level, truncate candidates, or weaken completeness.

## Decision

- `MarketSituationCandidateSet` owns the complete canonical candidate universe and the feature/context/configuration identities that establish it. It is analytical evidence, not a setup, plan, prediction, or execution instruction.
- The candidate-set ordering preserves the existing `market-situation-v1` role, price, source-precedence, and LevelId ordering. A final canonical serialized-level tie-break makes the remaining equal-key order independent of collection, dictionary, persistence, or provider enumeration order.
- `CandidateSetId` is a full 64-hex-character SHA-256 commitment to all candidate records and material scope identities. It excludes wall-clock, retrieval, evaluation, persistence, UI, and database timing. Reordering the same canonical universe does not change it; any material addition, removal, price, role, or provenance change does.
- `CompactMarketSituationAssessment` references `CandidateSetId` and retains the selected support/resistance levels, interaction geometry, primary evidence, bounded selection summaries, exact feature/context/configuration identities, quality/completeness evidence, candidate counts, and deterministic assessment identity.
- Compact interactions retain `LevelId` plus geometry and reuse direct selected-level provenance; they do not duplicate the complete `ImportantPriceLevel` in each interaction or embed losing candidates.
- The existing `MarketSituationAssessment` with `EligibleLevels` remains the explicit legacy compatibility projection. Existing v1 rows are read deliberately as legacy evidence; normal output projects a bounded selected/count view and never emits `EligibleLevels`. MarketReaction receives selected compact evidence, not the candidate universe.
- `market-situation-persistence-v2` identifies the compact normalized envelope. `20261127170000_AddNormalizedMarketSituationPersistence` adds one immutable candidate-set header, normalized source provenance, ordered scalar member rows, and nullable v2 discriminator/reference/digest fields to `market_situation_assessment`. Legacy rows remain null-discriminator rows and are not backfilled or rewritten.
- Candidate evidence is stored once and referenced by compact assessments. `CandidateSetId` uses a binary-collated 64-character SHA-256 key; source identity is likewise a full digest. Immutable collision checks compare header digests, counts, source material, and canonical member content before accepting replay.
- Candidate members are inserted as bounded `SqlBulkCopy` batches (default 1,000, infrastructure-configured), and header/source/member/completion/assessment operations commit in one SQL transaction. A 16 KiB compact assessment is the largest single v2 analytical payload parameter. Full candidate evidence never becomes one JSON or individual insert/round trip.
- A candidate set is marked complete only after exact member-count verification. A compact assessment references the completed set in the same transaction; cancellation or failure rolls back the whole write, preventing a referable incomplete set and making retry safe.
- Candidate evidence is not silently truncated. Batch 1 compact serializations were 3,992 bytes for a simultaneous-interaction case and 2,600 bytes for 100,005 analytical candidates. Batch 2 persisted 100,005 normalized members in 101 batches; the compact SQL JSON was 4,065 bytes. The persisted compact safeguard is enforced at 16 KiB.
- Normal `ScannerState`, opportunity list/detail, symbol/current state, MarketReaction input, and Blazor representations contain only selected support/resistance evidence, interactions, primary result, versions/configuration, quality/completeness, bounded selection evidence, counts, and `CandidateSetId`. They are enforced below 32 KiB and release the candidate-set reference after evaluation/persistence/reaction processing.
- The existing `/api/v1` routes use the compact shape because the application has no external API-stability contract, all checked-in consumers are updated together, and keeping a normal legacy route would preserve an unsafe multi-megabyte default. The route version is retained; the persisted `market-situation-persistence-v1`/v2 distinction remains explicit in the read model.
- Full evidence is read only through explicit `GET /api/v1/market-situations/{assessmentId}/candidates` keyset/ordinal paging. SQL pages directly with `(CandidateSetId, Ordinal)`, never hydrates the complete set, deduplicates source records per page, and returns deterministic continuation ordinals. Direct selected-member lookup uses `(CandidateSetId, LevelId)`.
- The initial forensic policy is 64 default/maximum members and 64 KiB serialized maximum. The 100,005-member measurement produced a 30,980-byte 64-member page. A page that exceeds the operational byte ceiling fails explicitly rather than truncating. Normal read models measured 3,463 bytes (small) and 3,473 bytes (100,005 candidates).
- Legacy rows may produce only an explicit bounded legacy current projection. A forensic legacy request returns `LegacyCandidateEvidenceUnavailable`; no normalized candidate rows are fabricated or backfilled.
- Persistence health is separate from analytical completeness. Successful analysis may produce a valid compact result before a persistence adapter fails, and that later failure cannot rewrite selected levels or `ContextMode`.
- A bounded application-terminal outcome is first-failure-wins. Abnormal application, background-service, provider, startup/configuration, or persistence-terminal outcomes retain the first safe reason/component/timestamp and set process exit code 1; expected requested shutdown and approved duration completion remain exit 0. Later cancellation cannot erase an established failure.
- The default `StopHost` background-service exception policy remains. `ScannerRunnerService` records terminal state before rethrowing; other validation/report service failures do the same. Artifact finalization remains graceful where possible; `FailFast` is not used.
- Development validation diagnostics remain a bounded sidecar. They summarize normalized MarketSituation writes, successes/failures, latency, compact bytes, maximum candidate/member-batch counts, candidate-set/source create/reuse, final channel capacity/depth, writer waits, operational enqueue-attempt age, prior-session warm-up outcomes, terminal outcome, duration gate, and validation result. No raw candidate/member arrays are included.
- Queue capacity remains 5,000, full mode remains `Wait`, and no events are dropped or analytically rebated. Oldest-age instrumentation is an operational enqueue-attempt age, so it includes a single blocked writer when capacity is reached; it is not market event time.
- Validation-launcher success requires matching child exit code, terminal outcome, shutdown trigger, configured/observed duration gate, diagnostics validity, artifact integrity, and validation-success markers. Missing, malformed, incomplete, terminal-failure, or contradictory evidence fails conservatively, including exit 0 plus ApplicationFailure. Process exit alone is insufficient.
- The analytical definition remains `market-situation-v1`; `market-reaction-v1` remains unchanged and can project domain-equivalent pinned level/zone evidence. No scanner configuration version bump is required.
- Raw historical trades remain unpersisted. A.2.6 remains paused through the completed corrective Batches 3-4 and pending Batch 5; `multi-session-structure-v1` and its pending Batch 2 direction are not changed.

## Consequences

- Batch 1 proves deterministic identity, analytical equivalence, reaction compatibility, legacy readability, bounded compact output, and collision rejection. Batch 2 proves clean/existing migration, idempotent replay, normalized large-set persistence, rollback/ retry safety, and immutable conflict detection.
- Compact assessment identity changes from the legacy v1 identity because the full candidate array is replaced by its full SHA-256 commitment. Legacy rows retain their existing shape and identity; future v2 writes must be distinguishable by the versioned envelope and must never reuse a legacy row as if it were v2.
- Production persistence and current production paths now use compact v2 evidence. Normal payload size is independent of candidate count, selected provenance remains explainable, and losing candidates require explicit forensic paging.
- Correction Batches 1-4 are complete. Batch 5 offline, guarded-SQL, 100,005-candidate reuse, and sustained hosted validation pass. A meaningful regular-session live run remains pending; the corrective checkpoint is not closed and queue policy remains unchanged.
